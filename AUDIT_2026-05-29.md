## TL;DR

The codebase is in **good shape**. Six modules were built incrementally but to a
remarkably consistent template — there is far less drift than the brief
anticipated. The audit found **4 safe-fixes** (dead files + one unused const,
zero behavior change), a short **flag-for-Ben** queue (all judgment calls, none
urgent), and a few **report-only** notes. The public-surface safety model
(`convex/public.ts`) is correct and was not touched.

## Area 1 — Cross-module consistency

**Verdict: strong.** The de-facto best pattern is well established and followed
almost everywhere:

- **Convex modules:** one file per domain; `assertMember(ctx, workspaceId)` as the
  first line of every authed handler; shared validators declared at file top;
  `list*` queries as a single indexed `.take(N)` read with sort/filter done
  client-side; partial-update mutations using the `...(arg !== undefined ? {…} : {})`
  spread; consistent `trim() || undefined` normalization; FK args validated against
  the same workspace before write.
- **Client pages:** `'use client'` → `useWorkspace()` → `useQuery`/`useMutation` →
  seed-on-first-visit guarded by a `useRef` → `useMemo` lookup maps → identical
  loading / empty / list states → `Row` + `FilterPill` subcomponents → `ConfirmModal`
  for deletes → form modals that own no persistence (parent saves).
- **lib helpers:** the `{ label, dot, text }` status-style triplet + a defensive
  `xOf()` reader + an `X_OPTIONS` array, mirrored across `guests`/`budget`/`vendors`.

**Minor deviations (cosmetic, flag-for-Ben):**
1. Query naming isn't uniform: `guests.list` / `tables.list` / `seatAssignments.list`
   vs `budget.listLineItems` / `vendors.listVendors` / `timeline.listItems`.
   Renaming would touch every call site + is purely cosmetic.
2. `GuestFormModal` differs slightly from the other three form modals: it disables
   submit with `saving || !name.trim()` (others just `saving`) and its panel lacks
   the `max-h-[90vh] overflow-y-auto` the others have.
3. `SeatingCanvas` builds its lookup maps (`guestMap`, `assignmentsByTable`) inline
   on every render; the pages memoize equivalent maps.

## Area 3 — Duplication that could be shared

All **flag-for-Ben** (judgment calls; the brief warns against over-abstraction):

1. **`FilterPill`** — defined verbatim in both `guests/page.tsx` and
   `vendors/page.tsx`. Cleanest, lowest-risk consolidation candidate
   (→ `app/components/FilterPill.tsx`).
2. **Modal shell** — the backdrop + panel + `stopPropagation` wrapper
   (`fixed inset-0 … rgba(26,31,46,0.3)` …) is repeated in `ConfirmModal` and all
   four form modals. A `<ModalShell>` would remove ~10 lines × 5 files, but touches
   every dialog → verify carefully.
3. **List-row hover actions** (Edit/Delete reveal-on-hover) repeated across every
   list row. Low value; abstracting risks coupling unlike rows.
4. **Budget ↔ Vendors category CRUD** (`seedDefaultCategories`, add/rename/
   delete-when-empty) are near-identical by intent. A generic helper is possible but
   adds Convex indirection for little gain. **Report: leave as an intentional mirror.**
5. Status unions are duplicated between `schema.ts` (inline) and each module's
   top-of-file `*Validator`. Minor.

## Area 4 — Convex layer

- **`workspaces.joinByInviteCode` scans all workspaces** (`.take(200)` + `Array.find`)
  — explicitly documented as prototype-acceptable. There is no index on `inviteCode`.
  **Flag-for-Ben / report:** a real fix needs a schema index, which is outside this
  pass's boundaries (no schema changes). Fine at current scale.
- **Indexes look complete and used.** `by_vendorId` on both `budgetLineItems` and
  `timelineItems` is exercised by `vendors.removeVendor`'s graceful detach. Good.
- **`public.getPublicSite`** does `.take(500)` on timeline items then filters
  `isPublic` in memory — fine at scale; **report-only (public.ts — do not modify).**
- **`workspaces.listMine`** loads workspace + members + member users per membership.
  Bounded (≤20 memberships, ≤2 members each) — not a real N+1.

## Area 5 — Inefficiencies / correctness smells

- **`useQuery(...) ?? []` in `useMemo` deps** (budget/guests/vendors/timeline pages)
  → the 7 `exhaustive-deps` warnings. A fresh `[]` identity each render recomputes
  the memo *while loading*; behavior is correct. **Flag-for-Ben** (consistency
  cleanup touching 4 files, low value) — or leave.
- **`SeatingCanvas`**: 3× setState-in-effect + `Date.now()` in render (4 of the 6
  lint errors). Working Konva/real-time code; restructuring carries the highest
  regression risk in the app. **Flag-for-Ben / report — do not "tidy."**
- **`layout.tsx:62`, `seating/page.tsx:115`, `invite/page.tsx:42`** — the remaining
  setState-in-effect lint errors. All working. **Report / flag.**
- **`cursors.upsert` trusts a client-supplied `userId`/`label`** rather than deriving
  identity from auth — a workspace member could write a cursor row under another
  member's id/label. **Report (low severity):** ephemeral presence, workspace-scoped
  to ≤2 members, `assertMember` still gates workspace access. Not in `public.ts`, but
  identity-adjacent — flagged, not auto-touched.
- **`cursors.remove` skips `assertMember`** (best-effort on unmount-after-logout, by
  design) — any authed user could delete any cursor row. **Report (low severity):**
  ephemeral only.

## Phase 3 — Flag-for-Ben decision queue

Ordered roughly by value-to-risk. **None are urgent; none should ship to prod
without a deliberate, separate decision.**

1. **Extract a shared `FilterPill`** (guests + vendors). Lowest risk, small win.
2. **Delete `convex/seed.ts`** (dead). Trivial, but regenerates the Convex `api`
   surface — do it in a Convex-aware change, not this pass.
3. **Normalize the `useQuery(...) ?? []` memo idiom** to clear the 7 exhaustive-deps
   warnings. Behavior-neutral but touches 4 pages.
4. **Extract a `<ModalShell>`** for the 5 dialogs. Moderate win, touches every modal.
5. **Unify query naming** (`list` vs `listX`). Cosmetic; touches all call sites.
6. **`SeatingCanvas` react-hooks errors** (setState-in-effect, `Date.now()` in
   render). Real lint debt, but highest-regression-risk code — only with care + a
   manual seating smoke test.
7. **`cursors` trust model** (client-supplied `userId`, no `assertMember` on remove).
   Derive identity server-side. Low severity; worth doing before multi-user scale.
8. **`joinByInviteCode` full-table scan** — add a `by_inviteCode` index (schema
   change, so out of scope here).
